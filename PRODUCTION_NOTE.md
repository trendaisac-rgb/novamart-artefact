# Production note: NovaMart internal assistant

**Platform.** OpenAI. The prototype leans on three things that are native there: reliable tool calling with strict schemas (Responses API), automatic prompt caching for the fixed prefix (rules, catalog, tool schemas, most of every request), and cheap model tiers. Everything runs on `gpt-6-luna`; `gpt-6.1-sol` only for the question types where the evals show Luna failing, and a different model as judge. The provider boundary is one file, so this is not lock-in. If NovaMart is already a Google Cloud and Workspace shop, Gemini Enterprise is the first alternative I would evaluate, since identity and document connectors would come solved. I would decide by running the same eval suite on both.

**Managed offering vs. custom build.** A hybrid. ChatGPT Enterprise (or Gemini Enterprise) for the general assistant office staff already want: drafting, summarizing, searching company files. It is live in days. The store-floor assistant stays custom and small, because its value is in three rules a general chat product only treats as suggestions: cite or decline, a structured outcome (answered, declined, escalated) Operations can measure, and an eval suite that blocks a bad release. Custom means one function, retrieval, the tools that touch NovaMart's systems, and the evals; not a platform.

**Connecting real data.** Policies: today in PDFs, SharePoint and emails. Convert them to one markdown file per policy, one heading per rule, owned by Operations in Git; a merge reloads the database and runs the evals. This is the highest-leverage step, because most "the assistant was wrong" cases are "the document was wrong or stale". Orders: a read-only client with the same `get_order_status` contract as the mock, authenticated per employee. Tickets: the escalation tool writes to the helpdesk NovaMart already uses. Retrieval moves to hybrid (keyword plus pgvector in the same Postgres) with filters for region, store format and effective date, behind the same `search()` contract.

**Security and governance.** SSO through NovaMart's identity provider, with store and role on every request and row level security scoped by store. Tools are allow-listed and read-only, except ticket creation; the model gets functions, never credentials. No customer data in prompts beyond the order the employee asked about. Zero data retention with the provider. Every answer stored with its trace (question, searches, sections read, tool calls, status, cost), so any answer can be audited back to a document version. Documents carry an owner and a review date. Refunds above a limit, fraud and exceptions stay human: the assistant explains the rule and opens the ticket, it does not approve.

**Quality over time.** The eval suite becomes a release gate in CI: no prompt, retrieval or document change ships below the threshold, and every fixed failure becomes a new case. In production, four signals: decline and escalation rate per topic (a rise means a documentation gap; the prototype's own eval run showed a prompt fix shifting this rate), thumbs up/down from employees, a weekly sample graded by the judge and spot-checked by Operations, and latency and cost per answer from the trace. The knowledge gap report goes to the ops lead every week.

**Rollout.** Weeks 1–2: documents converted and owned, two pilot stores, Operations reads every escalation. Weeks 3–4: real order and ticket systems, eval gate in CI. Month 2: all stores, gap loop running weekly. It is useful from day one because it is allowed to say "not covered", and someone is listening when it does.

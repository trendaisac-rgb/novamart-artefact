# Production note: NovaMart internal assistant

**Platform.** I would keep OpenAI for production. The prototype depends on three things that are native there: reliable tool calling with strict schemas on the Responses API, automatic prompt caching for the fixed prefix (rules, catalog, tool schemas, which is most of every request), and cheap model tiers (the prototype runs entirely on `gpt-6-luna`; `gpt-6.1-sol` only for the classes of questions where evals show Luna failing, and a different model from the agent as the judge). The provider boundary is one file, so this is not a lock-in decision. If NovaMart is already standardized on Google Cloud and Workspace, Gemini Enterprise is the first alternative I would evaluate, because identity and document connectors would already be solved; I would decide by running the same eval suite on both, not by preference.

**Managed offering vs. custom build.** A hybrid. ChatGPT Enterprise is the right tool for the general assistant office staff already want: drafting, summarizing, searching company files. It gets running in days. The store-floor assistant is different: it carries NovaMart's rules, and three of them are hard to enforce in a general chat product: cite or decline, the structured `respond` contract with a status Operations can measure, and an eval suite that blocks a bad release. So I would keep that part custom and small: one function, the retrieval layer, the tools that talk to NovaMart's systems, and the evals. A fully managed product makes those rules suggestions; a fully custom platform spends the first month on plumbing.

**Connecting real data.** Three sources, three patterns. (1) Policies: today they live in PDFs, SharePoint pages and emails. I would convert them into one markdown file per policy with a heading per rule, owned by Operations in Git. A merge loads them into Postgres and runs the eval suite. This is the highest-leverage step: most "the assistant was wrong" cases I have seen were "the document was wrong or stale". (2) Orders: a read-only client with the same `get_order_status` contract as the mock, authenticated per employee so audit logs show who looked up what. (3) Tickets: the escalation tool writes to the helpdesk NovaMart already uses. Retrieval moves to hybrid (keyword plus pgvector embeddings in the same Postgres) with metadata filters for region, store format and effective date, behind the same `search()` contract; the catalog in the instructions stays, because it drives the decline behavior.

**Security and governance.** SSO through NovaMart's identity provider, with store and role in the token on every request, and row level security scoped by store. Tools are allow-listed and read-only except ticket creation; the model never gets credentials, it gets functions. No customer data in prompts beyond what the order tool returns for the order the employee asked about. Zero data retention with the model provider, which OpenAI offers for enterprise API use, and responses not stored on their side. Every answer stored with its trace: question, searches, sections read, tool calls, status, sources and token cost, so any answer can be audited back to a document version. Documents carry an owner and a review date; a policy past its date is flagged in the catalog. Money above a limit, fraud and exceptions stay human-gated: the assistant explains the rule and opens the ticket, it does not approve.

**Evaluating and monitoring quality.** The eval suite becomes a release gate in CI: no prompt, retrieval or document change ships below the threshold, and every fixed failure becomes a case so it cannot regress silently. In production, four signals: decline rate per topic (rising means a documentation gap; falling after a new document confirms it closed), thumbs up/down from employees, a weekly sample of answers graded by the judge and spot-checked by Operations, and latency plus cost per answer, which the trace already records. The knowledge gap report goes to the ops lead weekly with the themes to document.

**Rollout.** Weeks 1 and 2: documents converted and owned, two pilot stores, Operations reading every escalation. Weeks 3 and 4: order and ticket tools on real systems, eval gate in CI. Month 2: all stores, gap loop running weekly. The assistant is useful on day one because it is allowed to say "not covered", and someone is listening when it does.
